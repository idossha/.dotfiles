# Orchestrator

Delegate when an independent result would reduce parent context or unblock useful concurrent work.
The parent remains responsible for decisions, integration, verification, and the user's complete outcome.

## Choose the owner

- Use the active harness's supported subagent facility for bounded in-session tasks.
- FirstMate owns a persistent fleet when explicitly selected; Herdr exposes sessions and Treehouse owns
  writer worktrees. Do not build a second fleet manager out of ad hoc panes.
- GNHF owns bounded unattended iterations when requested. Use its installed guide and the shared CLI
  for launch/recovery; the parent reviews its commits and evidence.
- If no suitable delegation facility exists, perform the work locally. Do not install a new
  orchestrator merely because a task touches several files.

## Task contract

1. Assign one independently completable question or change with clear input and output boundaries.
2. Provide the user outcome, authorization limits, relevant instructions and skills, exact reading and
   writing paths, already-known evidence, verification, and expected result.
3. Confirm the facility's current context-inheritance behavior. Never assume a child receives either
   all or none of the parent conversation.
4. Give each concurrent writer an exclusive Treehouse worktree or explicitly disjoint files within
   an already-owned task. A standalone writer uses a durable lease; do not mix lifecycle owners.
5. Use the model requested by the user or established session configuration. Capability checks and
   bounded tasks survive provider changes better than a hard-coded role/model roster.
6. Send independent tasks concurrently when supported. Keep dependent steps sequential.
7. Track task identity, owner, worktree/lease, progress and completion. A pane title or an idle display
   alone is not evidence that a task succeeded.
8. Read every result; integrate changes, run relevant checks, and return leases only after landing.

Do not delegate a handful of tool calls, a preference decision only the user can make, or a redundant
review without a concrete unresolved risk. Do not repeat authority questions already answered.
